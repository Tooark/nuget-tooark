# Release Notes v2.3.6

Data de lançamento: 15/11/2026

## 🆕 Resumo

Versão de manutenção só com atualização de dependências para corrigir vulnerabilidades. Não há mudanças de código, de comportamento ou de API pública. Não há breaking changes.

> ⚠️ **Suporte estendido até dezembro de 2026**: a linha v2, que encerraria em novembro de 2026, continua recebendo **correções de segurança até dezembro de 2026**. Depois dessa data ela não recebe mais atualizações de dependências nem correções de segurança. Correções de bugs e funcionalidades novas já não entram nesta linha.
>
> ℹ️ **Migração necessária**: para continuar recebendo atualizações e correções de segurança, é necessário **migrar para a linha v4.x**, que é a versão ativa em desenvolvimento. Consulte as release notes das versões v3.0.0 e v4.0.0 para o mapa de breaking changes de cada salto de major.

---

## Segurança

- **`System.Security.Cryptography.Xml`** 8.0.4 → **8.0.5**: corrige a CVE-2026-96958, a CVE-2026-96959 e a CVE-2026-96960 (negação de serviço, severidade alta) e a CVE-2026-96222 (spoofing, severidade alta).
- **`System.Security.Cryptography.Pkcs`** fixado em **8.0.2**: corrige a CVE-2026-84008 (negação de serviço, severidade alta) e a CVE-2026-70162 (negação de serviço, severidade moderada). Chegava na 8.0.1 por transitividade do `System.Security.Cryptography.Xml`.
- **`Microsoft.AspNetCore.WebUtilities`** fixado em **2.3.14**: corrige a CVE-2026-118750 (negação de serviço no ASP.NET Core, severidade moderada, [GHSA-6527-9fp8-r4x6](https://github.com/advisories/GHSA-6527-9fp8-r4x6)). Chegava na 2.3.11 por transitividade do `Microsoft.AspNetCore.Http`, cujo nuspec ainda aceita versões vulneráveis; por isso o pin é explícito.
- `Microsoft.AspNetCore.Http`, `Microsoft.AspNetCore.Mvc` e `Microsoft.AspNetCore.Mvc.Core` 2.3.12 → **2.3.14**.
- **Servicing de novembro do .NET 8**: `Microsoft.AspNetCore.Authentication.JwtBearer` e `Microsoft.Extensions.Localization` 8.0.30 → **8.0.34**.
- Verificação `dotnet list package --vulnerable --include-transitive` sem nenhum pacote vulnerável em todos os projetos da solução.

## Build

- **Publicação por Trusted Publishing**: o workflow de release deixa de usar uma API key guardada no repositório e passa a trocar o token OIDC do GitHub por uma chave temporária do nuget.org (`NuGet/login`), como a linha 4.x.
- Os pacotes são publicados **antes** de a tag e a GitHub Release existirem, com `--skip-duplicate`: uma falha no meio da publicação não deixa uma versão marcada como lançada pela metade.
- Build, publicação e release rodam em jobs separados, cada um com a menor permissão possível.
- O workflow é interrompido com um aviso quando a tag da versão já existe.
- A GitHub Release desta linha não é marcada como a mais recente do repositório.

## Impacto

- Sem breaking changes e sem alterações na API pública dos pacotes.
- Com o pin transitivo habilitado, as versões corrigidas entram no nuspec dos pacotes que as recebem por transitividade: quem atualiza o Tooark passa a resolver as versões corrigidas sem precisar fixá-las na aplicação.
- As correções do servicing ficam no runtime: a aplicação precisa do runtime 8.0.34 ou posterior.
- Compatível com .NET 8.0+.
- Build limpo (0 avisos, 0 erros) e suíte completa de testes aprovada (3483 testes em net8.0).
