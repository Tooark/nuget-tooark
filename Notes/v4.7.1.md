# Release Notes v4.7.1

Data de lançamento: 16/10/2026

## 🆕 Resumo

Versão de manutenção, sem alteração de comportamento nos pacotes: atualiza os SDKs da AWS usados pelo `Tooark.Storage.Aws` e pelo `Tooark.Secrets.Aws`, passa o `Copyright` dos metadados para 2026 e leva aos pacotes a documentação revisada depois da v4.7.0, com o link de cada README para o site de documentação e o cruzamento entre o `AddTooarkModelStateEnvelope` e o `AddTooarkValidationAttributes`. Acompanha o site de documentação do repositório, em `tooark.com/nuget-tooark`. Não há breaking changes.

---

## Modificado

- **Dependências** (só os pacotes indicados recebem a versão transitiva nova):
  - `AWSSDK.S3` 4.0.103.4 → 4.0.104.3 (`Tooark.Storage.Aws`);
  - `AWSSDK.SecretsManager` 4.0.100.14 → 4.0.100.17 e `AWSSDK.SimpleSystemsManagement` 4.0.104 → 4.0.104.3 (`Tooark.Secrets.Aws`).
- **Metadados dos pacotes** — `Copyright` passa de 2025 para 2026 no nuspec de todos os pacotes.

## Documentação

- **READMEs** (raiz e pacotes, en/pt-BR): cada um ganha, acima do seletor de idioma, a linha 📖 com o link para a página do pacote no site de documentação, para todos os pacotes e para a referência da API, no idioma do README. Quem chega pelo NuGet passa a ter o caminho para a busca e a navegação entre pacotes. O README raiz aponta também para as notas de release.
- **README raiz** (en/pt-BR): a seção de instalação deixa de dizer que o agregador instala tudo. Mostra o agregador, os provedores de storage e de segredos instalados à parte (um por nuvem) e o que o `AddTooarkService` deixa de fora: a unidade de trabalho, o SSO com OpenID Connect, o storage e os segredos.
- **`Tooark.AspNetCore` e `Tooark.Attributes`** — com só o `AddTooarkModelStateEnvelope` registrado, o campo ausente com atributo do Tooark recebe a chave `Field.Required` traduzida e também o `The Email field is required.` do `[Required]` que o MVC infere, e a documentação não apontava o `AddTooarkValidationAttributes`, que retira a segunda mensagem. Só documentação; o comportamento não muda.
  - Docs XML (IntelliSense): o envelope explica que muda o corpo da resposta, não as mensagens, e os dois registros se referenciam com `<seealso>`. O `GetErrors` e o `TooarkValidationAttribute` ganham um parágrafo sobre as duas mensagens do campo ausente.
  - READMEs do `Tooark.AspNetCore` e do `Tooark.Dtos` (en/pt-BR) registram o mesmo cruzamento.

## Infraestrutura do repositório

- **Site de documentação** em `tooark.com/nuget-tooark`, com os guias dos 26 pacotes, busca e a referência da API, em inglês e em português. O `docs/build.py` monta o site com o DocFX 2.81.0 a partir dos READMEs e das docs XML, sem texto escrito duas vezes, e falha em script inline, handler inline ou imagem de outro domínio, para respeitar a CSP do `tooark.com`. O `pages.yml` publica o site a cada push na `main` que toque a documentação ou o código, sem relação com a publicação no NuGet, e o `ci.yml` confere os grupos de pacotes do site em todo pull request (`python docs/build.py --check`).
- **GitHub Actions**: `actions/upload-pages-artifact` 3 → 5 no `pages.yml` (PR #67).
- **Testes**: `xunit.v3` 4.0.1 → 4.0.2 e `xunit.runner.visualstudio` 4.0.0 → 4.0.1 (PR #70). Só o projeto de testes usa; nenhum pacote publicado muda por eles.

## Impacto

- Compatível: nenhuma API pública muda. Quem usa o `Tooark.Storage.Aws` ou o `Tooark.Secrets.Aws` recebe os SDKs da AWS atualizados como dependência transitiva; os demais pacotes são republicados na v4.7.1 só com os metadados e a documentação novos.
- Compatível com .NET 8.0+ e .NET 10.0+.
